# Qualified image promotion and retrieval

Owner: repository maintainer (Nipun / Cyphire2025). Reviewed 2026-09-27; review by 2026-12-25.

The supported production activation entrypoint is `scripts/release_current.py`. Activation requires `RELEASE_ARTIFACT_MANIFEST` and verifies the signed inventory, each OCI image's provenance and SPDX SBOM attestation, exact source commit, main branch, repository, workflow identity, GitHub OIDC issuer, hosted runner and image config digest. Failure occurs before database backup/migration, role provisioning, writer shutdown or storage cutover. Local `prepare` remains available for isolated qualification but cannot authorize production activation.

CI builds backend and frontend once, runs the joined production-image qualification, inventories full images including OS packages, and scans the inventories with pinned Grype. The next mandatory policy gate rejects unreviewed high/critical matches. Exact scoped image dispositions require live parser/native-code probes, matching image bytes, expiry and production isolation controls; the separate ecdsa exception additionally requires its import/source review. Mitigated unpatched findings stay explicit. No `only-fixed` suppression is used. The signed qualification index binds the Docker archive checksum, image config digest, SBOM checksum, and canonical dependency-policy fingerprint. Backend export also requires matching actual advisory-condition evidence.

The `publish-qualified-artifacts` job runs after those gates on a main-branch push. It uses the `production-artifacts` environment, verifies the signed index, loads the same archives without rebuilding, refuses an existing commit tag with different config bytes (an interrupted identical promotion can resume), pushes to the reviewed GHCR namespace, checks digest/config readback, and signs provenance, SBOM and release inventory. It publishes a separately retrievable GitHub release named `release-<full commit>`. It does not deploy or roll back a database.

The trust root is `tooling/release-trust.json`; it is reviewed source, never selected from a downloaded manifest. Verification delegates cryptography to `gh attestation verify` with explicit source/workflow restrictions. Attestation is a trusted workflow statement, not an assertion of a particular SLSA level. Initial 27 September inspection found main protection, rulesets and environments absent. The coordinating workstream then applied and read back main history protection, main-only owner-reviewed promotion with admin bypass disabled, and release immutability. [Remote settings evidence](remediation/github-protection-evidence.json) records both states. The repository has one collaborator. The [concrete setup recommendation](remediation/github-promotion-prerequisites.md) preserves normal main pushes while adding history protection, an explicitly named main-only environment and honest owner release approval. Independent review cannot be claimed with one reviewer approving their own work. Merely naming an environment in YAML does not configure those protections.

This repository was verified public; the proposed environment protections are available for public repositories. Registry authentication, supported GH CLI, branch/environment configuration, package retention and actual signature issuance remain external prerequisites. There is no unsigned fallback. This workflow has not yet been published/executed as evidence of remote issuance. Enable release immutability before publishing the complete draft inventory; that protects release assets/tags, not the separate GHCR package against deletion.

An operator authenticated to GitHub and the private registry can retrieve an approved current or previous release into a **new** directory:

```bash
python3 scripts/release_artifacts.py retrieve --revision FULL_40_CHARACTER_COMMIT --directory /protected/releases/FULL_40_CHARACTER_COMMIT
```

This verifies the inventory and both OCI attestations, pulls by digest and checks config/revision. It does not replace running containers or restore data. Retain the current and at least two previous qualified releases for 180 days: GHCR manifests/layers/attestations, GitHub release inventory/SBOM assets and approved configuration/schema records. CI's 30-day transport archive is **not** the rollback retention store. Configure and test retention externally; policy source is not evidence that retention is enabled.

For an approved deployment, set `RELEASE_ARTIFACT_MANIFEST` to the verified inventory for both `prepare` and `activate`; follow `CURRENT_RELEASE_AND_STORAGE.md` for exact checkout, traffic pause, archive validation, restricted identities, schema preflight, writer drain, copied object storage and readiness. Preparation pulls qualified images instead of rebuilding. Activation re-verifies them, rechecks advisory review expiry against the signed policy fingerprint, and checks prepared local image IDs. Historical retrieval is allowed after a review expires, but activation and promotion fail until a newly qualified, signed review is supplied. Config SHA256 is read from the actual saved configuration blob and verified against the registry platform manifest; it is distinct from Docker containerd's local index/manifest ID. The verified local ID is used only for local container pinning. Failed migrations stop the release. Previous images require a separately reviewed schema-compatibility rehearsal; never automatically downgrade or overwrite the live database.

Container bases and bundled PostgreSQL/Redis/Nginx are digest-pinned. OS package installs may still resolve updates during a new build: the qualified image is promoted unchanged with its full SBOM/scan. Rebuilding a source commit is not asserted to reproduce identical bytes. Update PRs must regenerate locks/pins and pass qualification.
