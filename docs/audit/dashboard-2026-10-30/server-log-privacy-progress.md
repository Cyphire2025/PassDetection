# API/server exception log privacy

The API's registered unhandled-exception handler already emits a safe `error_type`/`request_id` event and a generic HTTP 500 envelope. The current Starlette middleware then re-raises the original exception. Installed Uvicorn H11 and HttpTools cycles log that exception with `exc_info`, reaching configured application JSON output or Uvicorn's separate default stderr handler. A synthetic SQLAlchemy `IntegrityError` with `hide_parameters=True` still carries its synthetic original driver message; hiding bound parameters does not remove that original message.

Both actual transport cycles were exercised without sockets using real FastAPI/RequestID/error-handler/formatter code and synthetic in-memory transports. All eight baseline cases emitted their synthetic private sentinel at the outer server sink, while the client response and the application's own unhandled event remained safe. Original before receipts remain unchanged in `api-unhandled-log-sink-before.json` and `api-unhandled-log-sink-httptools-before.json`. The eight equivalent after controls retain the outer diagnostic and HTTP 500 behavior and omit the private sentinel.

`server_diagnostics.py` now installs a logger-level filter on the actual `uvicorn.error` logger before handler fanout. It retains exception type/module, a validated request UUID and at most sixteen module/function/line frames. It removes exception arguments/messages, cached exception text, cached rendered message and stack text from that record. It does not modify the original exception, cause/context chain, SQLAlchemy original/parameters/statement, HTTP error envelope, ordinary operational messages or logger levels. Setup is idempotent. Application logging configures it, and the production worker installs it before its base constructor can replace handlers with Gunicorn's.

The pure identifier/frame algorithm moved into `exception_diagnostics.py`. The task module retains its public `diagnostic_name` alias, private `_frames` compatibility wrapper and original fallback string. The task result dataclass, whole failure-projection function and provider code allowlist compare exactly. Actual public aliases and runtime `typing.get_type_hints` resolution are also checked. `server-log-privacy-movement-proof.json` preserves original source, current hashes and the exact comparison/normalization limits. This shares value-free formatting without making server diagnostics depend on task-specific messages or provider classifications.

The final affected run passed 60 cases across the new sink suite and existing logging setup, Celery projection, private Celery, database parameter-policy and API error-envelope controls. The new eight-case sink suite failed eight of eight against the original runtime. Additional controls cover chained exceptions, pre-cached traceback/message data, handler fanout, bounded frame output, unchanged exception objects, invalid request IDs, ordinary operational messages/levels, optional structlog behavior, idempotent installation and worker-constructor ordering. The worker ordering unit uses a synthetic base modelling the separately inspected real Uvicorn constructor; it is not an executed Linux Gunicorn process.

All five current runtime owners were collected together with branches in the final affected run. Line/branch coverage is 100%/100% for the original task owner and relocated pure helper, 97.30%/83.33% for the server filter, 93.33%/100% for application logging and 100%/100% for the small worker. These are focused per-file measurements, not whole-backend coverage. `server-log-privacy-coverage-responsibility.json` transfers the real helper obligations and retains the old task floor/caps. Proposed critical guards are 95% line/90% branch for the helper and 95%/80% for the filter. No test was added merely to chase the filter's unexecuted repeat-marker branch to 100%.

Scoped Ruff and mypy pass, as do the existing 493 backend budgets and architecture boundaries. Five candidates are supplied separately; the shared budget file remains parent-owned. The original logger line/complexity/floor caps remain 153/5/90%, and the original task caps remain 93/9/90%. The final logger is 149 physical lines. An unrelated formatter expansion was reverted to the original layout while proving its entire AST unchanged, preserving the existing ceiling.

Access-log inspection was separate and read-only. Current Gunicorn source disables access logging; application setup raises `uvicorn.access` to WARNING. Focused Nginx excerpts omit query/referrer logging, redact public token paths, disable request-context HTTPS error logging and disable access logging for private MCP transfer paths. No Nginx process or additional access-log disclosure was reproduced in this lane, and no access configuration changed.

The current seven-file source fence and commands/results are in `server-log-privacy-reviewed-files.json` and `server-log-privacy-verification.json`. The original fifteen-file physical-read ledger remains historical. All data and exceptions used here were synthetic. This qualifies the local app/ASGI log sinks and source wiring, not live PostgreSQL/provider/Gunicorn/Linux/VPS behavior. No services remain running, no provider requests were sent, and frozen frontend sources were untouched.
