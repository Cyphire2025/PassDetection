# Dashboard group and AI inbox route review

Reviewed both original large route modules completely, followed their directly relevant application/authorization contracts, and preserved the existing public HTTP entry points while extracting cohesive implementation owners. The file records in `dashboard-routes-reviewed-files.json` bind **43 full reviews and four partial reviews** to the current raw SHA-256 of each source file. These are lane-specific coverage claims; they do not imply that all shared service implementations or the whole repository have been reviewed.

Three findings were reproduced against the preceding implementation and fixed:

- The public upload-token lookup returned the office-only `notes` field through the shared group DTO. The public use case now returns a copied DTO with `notes=None`. The database entity and authenticated create/list/update responses retain the original notes. The integration regression checks both public redaction and preservation of the saved note. The frontend only displays this field in the authenticated group overview.
- Inbox queries joined the maximum analysis timestamp without breaking ties. Two analyses created at the same timestamp could duplicate a message and inflate section counts, while the detail endpoint could select a different analysis. A window rank selects exactly one analysis per message, ordered by creation time and UUID. The inbox, counts and intelligence detail now choose the same analysis. The existing cross-agency/owner-isolation regression also verifies this tied-timestamp case.
- A malformed cursor containing a nonfinite JSON numeric rank escaped validation with `OverflowError`, producing a server error. The decoder now maps exactly that conversion error to the existing static 422 response. The expanded malformed-cursor test first failed against the preceding decoder; all 10 protocol/isolation tests pass after the one-exception addition.

`dashboard-route-before-regressions.txt` retains the two failures against the old implementation; `dashboard-route-after-regressions.txt` retains the initial passing verification.
