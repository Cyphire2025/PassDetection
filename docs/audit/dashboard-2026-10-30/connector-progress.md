# Dashboard desktop connector review

Read all **14 runtime Python modules** under `mcp-connector/src/gc_mcp_connector/` in full. Current byte hashes and file-specific review notes are in `connector-reviewed-files.json`. This is the dashboard's desktop connector; mobile application code was not reviewed or changed in this lane.

Reviewed credential storage, configured-origin/network authority, PKCE and callback validation, refresh rotation and cancellation, read-only catalog enforcement, startup-selected filesystem scope, upload/download integrity and atomic publication, error sanitization, duplicate-write behavior and backpressure. The runtime already separates these responsibilities into cohesive modules. Uploads and business tool calls are not transparently replayed; only idempotent delivery acknowledgement permits bounded retry. Transfer reads use bounded chunks, local transfer concurrency is capped at two, and remote sessions at four. These are source properties; no performance benchmark or zero-lag claim is made.

Found and fixed one concrete recovery bug in `cli.py`: every command called `vault.read()` first. The Windows vault parser tells users with malformed saved authorization to run `forget`, but `forget` repeated the same failing parse before it could remove that record. The explicit `forget` command now reaches the existing serialized deletion operation without reading/parsing the credential. Other commands retain their vault preflight before browser or network work. Dedicated target naming, permissions, rotating credential behavior, and server revocation remain unchanged.

Added three synthetic CLI tests: successful explicit cleanup despite a failing parser, safe propagation of deletion failure without a false success message, and preserving sign-in's failing-vault preflight before discovery/browser activity. Tests substitute the vault and process lock and explicitly forbid HTTP transport. No stored user credentials were accessed.

Verification used the existing fresh `.tmp/dashboard-audit-venv` with matching reviewed connector dependency versions: MCP 2.2.0, httpx2 2.13.1 and pywin32 312. From `mcp-connector/`, the selected auth/callback/lifecycle/refresh/file/artifact/contact/media/proxy/read-only/instruction/CLI test files passed **163 tests in 9.00 seconds**. They use mocked HTTP/vault and synthetic fixtures; callback lifecycle tests bind isolated loopback listeners and forbid application/token endpoint traffic. The native mutex test uses a unique synthetic kernel object. All backend `*_tcp.py` fixtures and `test_windows_vault_native.py` were excluded from this run. No browser, actual credential vault, application authentication endpoint, provider, production service or Codex configuration was used.

Ruff lint passed for all runtime source and the new test. Formatting passed for the changed CLI and new test. The existing formatting debt in `contact_uploads.py` was subsequently cleaned with pinned Ruff 0.16.0. An exact comparison of `ast.dump(ast.parse(source), include_attributes=False)` before and after is equal, proving no code-structure change. Focused contact-upload/error tests passed **35 tests in 1.88 seconds**, and full runtime plus new CLI-test lint/format checks now pass (15 files formatted correctly). The prior 163-test suite was not repeated because this follow-up changes layout only. Original/current SHA evidence is in `connector-contact-format-verification.json`. No dependency lock, package version, configuration or qualification guidance changed. No unused runtime module or additional proven security defect was found in this focused manual review; this does not establish absence of vulnerabilities in unexercised deployment/native integration conditions.

The README's existing qualification boundary remains authoritative: real Codex/native vault sign-in, production access isolation and production transfers are not qualified by these tests. `connector-verification.json` records measurements and limitations.
