## Findings fixed

- Successful vision responses were buffered by `httpx.post` before their existing response-size checks. The shared bounded streaming helper now stops before the byte limit is exceeded, rejects non-identity response encoding before decompression, closes on cancellation and rejects redirects. Error response bodies are not downloaded or retained. Primary extraction, post-submission verification, ECR and Visa image editing use this helper while preserving their existing operation timeouts, model ordering, pacing and retry rules. Visa inline image text is also length-checked before base64 decoding.
- Post-submission verification could accept a candidate with a noncompletion `finishReason`, including `SAFETY` or `MAX_TOKENS`. It now follows the existing invalid-response/review outcome. Image editing similarly cannot publish an explicitly incomplete candidate. Missing finish reasons remain compatible with existing provider fixtures and responses.
- Verification deliveries were not bound to the durable claimed job's submission and revision. A mismatched delivery now rolls back its claim before any fallback, provider work or publication. The genuine queued delivery remains claimable.
- Processing claims could exceed the durable attempt budget. Exhausted queued or stale claims now dead-letter without incrementing attempts; a still-live final attempt remains busy.
- An expired Visa image worker could upload/publish an old result or fail/requeue/refund a newer attempt. Side effects and outcome changes now require the exact locked running claim/attempt. Each artifact gets a unique key, so an old attempt cannot overwrite or compensate a newer artifact. A synthetic recovery regression failed against the original worker body before the fix.
- A completion-log failure after a successful image publication could delete the committed artifact. Publication relinquishes the compensation candidate immediately after commit. A regression reproduced the deletion before the fix.
- An interrupted image upload had no durable cleanup intent. An encrypted cleanup tombstone is committed before upload, delayed beyond the existing worker's ten-minute hard limit, and cancelled atomically with successful library/job publication. Failed cleanup retains the tombstone for the existing cleanup scheduler. If a commit result is uncertain, compensation first checks the locked tombstone: an already committed publication has cancelled it and its artifact is preserved. This reuses the current table, cipher and scheduler; it requires no new migration, provider, service or VPS setup.
- Passport/group deletion already collected stored AI-library keys, but its cleanup namespace validation rejected them. The exact `passport-ai-library/` prefix is now accepted for deletion of those database-owned artifacts. Unrelated cleanup sources and lookalike prefixes remain rejected.
