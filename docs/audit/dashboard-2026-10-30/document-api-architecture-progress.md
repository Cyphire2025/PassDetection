# Document API architecture and filename workload

The original 388-line `document-distribution.api.ts` was fully reread with the actual workspace, manual-review and query/mutation callers before changes. The stable facade is now 14 lines. Four cohesive owners handle review/export (51 lines), verification/manual type checks (150), batch/finalization/assignment transport (146) and delivery (54). Shared public types occupy 18 lines and filename indexing 46. No proxy or callback-forwarding layer was introduced; complete existing method implementations live in their actual owners.

The deliberate optimization was measured through `documentDistributionApi.verifyDocuments`, with real current chunk/progress/manifest helpers and synthetic HTTP responses. A 512-file/512-replacement workload made 32 verification requests. The original implementation read replacement filename properties 81,920 times; the indexed implementation reads them 1,024 times, an 80-fold reduction for this workload. This is a measured property-access workload, not an HTTP throughput or production-capacity claim. The new auxiliary indexes use linear space in replacement and chunk/name associations. Duplicate names spanning many chunks still require work proportional to their output associations.

Manual-review selection retains the first exact-name replacement object. Finalization metadata retains every matching replacement in original input order, including duplicates and the same name across chunks. Unicode, case-sensitive names and object-prototype-like names remain exact strings without normalization. Counts, verification file order, receipt identity, candidate file offsets/reference identity, progress and capability stripping are asserted through the actual API entry. A response-count mismatch fails instead of manufacturing staging ownership; accepted flags without a confirmed passenger match cannot stage a receipt.

The optimization checkpoint and subsequent mechanical extraction are distinct. `document-api-architecture-provenance.json` preserves the entire original source, indexed checkpoint and all fifteen old-to-new method bindings. Complete method/signature ASTs match the indexed checkpoint. Fourteen original methods are unchanged even across the optimization. Both public type declarations, the private export filename function and ordered facade are preserved. Formatting comparisons retain emitted semantics; current import wiring and type checking validate the new owners.
