# Shared audit, observability and notification transports

Eleven retained runtime sources were physically read completely: the signed audit checkpoint codec/S3 adapter; operational event, StatsD, Sentry and both MCP log readers; shared FCM/APNs credential implementations and provider adapters. The original cohort contains1756 lines. Actual credential files were not read, provider requests were not made, and native app/client/ingress features remain outside this audit. Five matching-current previously full records are attributed separately rather than counted as new physical reads.

One source-backed defect was reproduced and fixed. Through the actual public checkpoint iterator, cancellation during native `get_object` returned control before the worker finished. Its later real botocore `StreamingBody` was never closed. The synthetic before probe produced one failed lifecycle assertion and three passing normal/signature/error controls. The original17 audit tests also passed before changes.

The S3 adapter now retains an owned native Future through response acquisition, bounded read and close. It drains those operations under repeated cancellation, closes a late response once and preserves the initiating cancellation. It uses the same default executor and copied context, with no shared engine or schema/configuration change. The real `asyncio.run` shutdown path is tested. A broken SDK close can still throw; the guarantee is exactly one cleanup attempt, with ordinary errors preserved and cleanup errors prevented from replacing an initiating cancellation.

All five other complete class methods, all six method signatures/defaults/runtime hints and the post-body signature/retention/identity verification tail remain AST equivalent. WORM/conditional publication, pagination, payload bounds and signing behavior are unchanged. The current229-line adapter remains one cohesive responsibility.

The final affected run passed30 cases:17 original plus13 new lifecycle/context/error/shutdown controls. Strict mypy, Ruff without fixes and formatting passed for the changed scope. Fresh isolated coverage measures92.913% lines and73.529% branches. One additive normal candidate and a90%/70% actual behavior critical proposal are handed to the central gate owners; no shared quality gate was edited here. The final receipt is `shared-observability-push-verification.json`, with source-equivalence, full/partial read records and raw synthetic receipts linked.

The other ten runtime sources are source-review results. Their fixed hosts, bounded diagnostics, safe payload/error projections and resource ownership were traced; this does not claim provider delivery, Sentry ingestion or live S3/PostgreSQL verification. No broad suites, build, browser run, deployment or production data access occurred. The main audit and final combined verification remain in progress.
