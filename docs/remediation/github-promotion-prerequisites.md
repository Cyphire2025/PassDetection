## Minimum setup compatible with normal pushes to main

1. Protect `main` against deletion and force pushes, including administrator bypass of those history protections. Normal fast-forward owner pushes can remain allowed, as requested. Do not describe this as independent change review. Requiring a pull request or pre-push status checks would change the currently authorized direct-push workflow; introduce that separately with an agreed candidate-branch/merge process. GitHub's protections distinguish these settings. [Protected branches](https://docs.github.com/en/repositories/configuring-branches-and-merges-in-your-repository/managing-protected-branches/about-protected-branches).

2. Create the `production-artifacts` environment. Select **only the branch `main`**, with no tag rule, using a custom deployment branch policy. Do not use `Protected branches only` while no protection exists: GitHub documents that this condition admits all branches when none are protected. Add `Cyphire2025` as the required reviewer, allow self-review, and disable administrator bypass. With one maintainer this is an explicit owner release decision, **not independent approval**. Preventing self-review with the same sole reviewer would deadlock promotion. The public repository can use these environment protections under current GitHub plans. [Deployment environments](https://docs.github.com/en/actions/reference/workflows-and-actions/deployments-and-environments), [managing environments](https://docs.github.com/en/actions/how-tos/deploy/configure-and-manage-deployments/manage-environments).

3. Enable repository release immutability for future releases. The workflow's `gh release create` with attached assets already performs draft creation, asset upload and final publication internally; this behavior was verified in the official CLI implementation and is not a new defect. Read the setting back before publication, and verify the resulting release's immutable status. This protection covers release assets and its Git tag; it does **not** make separate GHCR package manifests undeletable. [Release immutability](https://docs.github.com/en/code-security/concepts/supply-chain-security/immutable-releases), [enable and inspect](https://docs.github.com/en/rest/repos/repos#check-if-immutable-releases-are-enabled-for-a-repository), [CLI draft-before-upload implementation](https://github.com/cli/cli/blob/trunk/pkg/cmd/release/create/create.go#L461-L519).

4. Grant this repository's Actions workflow package-write access only to its backend/frontend GHCR packages and preserve the existing commit-specific registry namespace. Keep the default workflow token read-only; the already-separated publication job has narrowly scoped package/content/attestation write and OIDC permissions. The VPS needs authenticated read access, not package deletion or write permission. No production secrets belong in image build arguments or the public release assets.

5. Keep the current and at least two previous approved manifests, image layers, provenance/SBOM attestations and release assets for **at least 180 days**. Do not install a package cleanup job that can remove these releases. The 30-day Actions artifact retention is transport storage only. Record an accountable package owner and review any human or automation permission that can delete package versions. A documented retention duration is not an enforced external retention service. An independent retained copy would improve availability; its existence and restore behavior are currently unverified.
