  current source tenant/group, revision, content/name/phone fingerprint, key version,

  replacement candidates. Source-only locks avoid locking joined broadcast rows.
- Staff source listing uses selective cursor pages (default 25, max 50), name search
  with the existing trigram prefilter and a bounded candidate projection query.
- Explicit enrollment requires accepted source/current revisions, configured purpose
  and notice, permission evidence, plus a reviewed target for updates. Missing issuer
  and document type require explicit document-view attestation, not nationality or
  place-of-issue inference. Retry HMAC binds the complete enrollment payload.
- Lost/cancelled/compromised/disputed/rejected passport identities cannot be revived
  by enrolling a new scan. A reviewed renewal creates another identity for the same
  person. Later accepted issue dates can become future defaults; trip references freeze.
- Public replacement-candidate linkage requires a live grant/review version AND the
  fresh upload's own X-Upload-Session-ID capability. It binds one source to the selected
  person, preserves provisional status, and records a keyed digest of source fields
  and images. Staff must approve the source and acknowledge the selected-person
  association during enrollment. Changed content requires fresh association. Ordinary
  staff approval revision increments with unchanged content remain valid.
- Independent original copies are queued durably and performed server-side without
  loading document bodies into the worker. Global PostgreSQL copy admission <= 2,
  attempts <= 5, explicit provider timeout envelope, stable destinations, post-copy
  size/checksum checks and live authorization both before and after I/O.
  MIME-derived allowlisted extensions are durably bound before copying; copied MIME
  must match and cannot change between retries. Older extensionless exports use the
  existing validated archive handling rather than trusting a guessed filename.
- Shared private media policy permits JPEG/PNG/WebP/PDF <= 20 MiB. Pending, purged,
  unsupported, expired or unreadable assets cannot satisfy reuse requirements.
- Group/source deletion detaches operational FKs and preserves immutable provenance.
  Pending copies block unsafe source deletion. Cleanup consults retained ownership;
  copied originals cannot be deleted as incidental old-group assets.
- Future-reuse withdrawal immediately revokes historical access. Lawful current-trip
  snapshots retain their own referenced data until the operational source is removed.
  Asset purge/hard profile deletion immediately denies staff image/thumbnail access.
- Staff confirmation/single/bulk approval synchronizes the current participation once
  and records its accepted source extraction revision; it does not silently promote
  edited trip fields into retained identity evidence.
- ZIP preparation uses batched retained-asset authorization (<= 200 sources / 1,000 assets
  per query), rechecks immediately before and after rendering, and closes the spool if
  authority was removed during generation. MCP's existing re-preparation around upload
  also uses this guard. Previously published artifacts need their own download-time
  revocation checks; do not confuse generation guards with permanent artifact erasure.
