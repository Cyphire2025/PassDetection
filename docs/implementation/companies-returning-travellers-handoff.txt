  claim revocation and reconciliation. No silent movement of old company profiles.
- Current group metrics distinguish accepted participation, earlier actual travel
  and verified reuse completion. Reconciliation incompleteness is visible and

- Public returning collection offers WhatsApp, passport, configured individual code,
  and fresh collection. Masked candidate selection is phone-OTP scoped. Claims and
  grants use short-lived HttpOnly Strict cookies; secret capabilities never enter
  URLs, browser localStorage or API response bodies. Server-side authorization
  rechecks group/company/person/contact/document/policy revisions on protected reads.
- Independent Redis network/session request limits and persisted person-level proof
  budgets apply across routes. Missing production limiter/crypto configuration fails
  closed. Responses are private/no-store. Asset IDs are checked against the exact
  grant and retained owner before any object-store access.
- Review shows allowlisted extracted identity fields and protected, lazy document
  previews. Passport lifecycle/expiry is separate from identity proof. The six-
  calendar-month group-date rule is centralized in traveller_suitability.py; unknown
  itinerary/issuer/rule coverage never becomes an asserted destination clearance.
- Current trip requirements and custom questions are validated using existing
  collection rules. Only unchanged answers from the same trip may be restored.
  Completion creates one normal client-submitted source plus a frozen participation,
  requires current review/version evidence, is idempotent and still needs normal
  staff review. It never treats a provisional match as submission or approval.
- Updating a passport uses fresh document collection and a selected-person candidate
  association. Staff acceptance/enrollment is explicit; old accepted versions remain.
  Changing phone requires OTP on the new number, affects only the selected person,
  revokes old grants and preserves historical snapshots. Contact events are durable;
  external contact-change alert delivery is not configured in this release.
- Lost/cancelled/compromised lifecycle changes revoke affected grants and queue
  bounded operational review tasks. The committed change feed uses a company
  sequence so late commits cannot be skipped by a timestamp checkpoint. It does not
  write to external visa/ticketing systems.
- Excel/ZIP and MCP export history use one content-revision comparison rule, including
  edits to the same submission ID, additions and removals. Changes are represented
  in an Excel Changes sheet / ZIP changes.json. Export reads are bounded and check
  retained authority before and after generation.
- All new staff pages use the existing dashboard design. Search is debounced and
  cancellable; lists use bounded cursor pages; document payloads load on request.
  Fresh-upload entry remains available from returning verification/error states.

Implemented persistence, ingestion and storage slice
- Frozen additive persistence migration 0131_traveller_reuse. 0132_traveller_source_seek
  creates passport and linked WhatsApp source cursor indexes concurrently, recovers
  interrupted invalid indexes and verifies valid definitions. Operational impact/feed
  work follows as 0133; use release_manifest.json for the final exact schema head.
- Separate tenant/company scoped profile, passport, immutable evidence revision,
  original asset, contact history, individual code, participation, permission policy,
  claim, attempt budget, grant, match case, resumable job and change-event records.
  Historical group FKs preserve source company across populated reassignment.
- Recognition is preview only. No name/phone merge, invented OTP, permission grant,
  profile enrollment or current-trip participation is created by a matching job.
- Jobs read accepted submissions AND linked durable WhatsApp recipient/rejected rows.
  Source kind + UUID cursors use v2:<source_kind>:<UUID>; legacy UUID cursors remain
  compatible. Each UNION branch is capped before the final sort, so at most 303 rows
  reach it; final page <= 100. Exact configured individual code can propose a match;
  imported passport fields are not accepted proof. Unsuffixed primary code is used;
  merged phone-delivery alternate fields never imply another person's identity.
- Coverage is explicitly durable_saved_rows_only. The import follow-up now preserves
  all individual rejected rows within the existing 2,000-row workbook limit while
  returning only a bounded 500-row preview. A real 700-person XLSX with one phone was
  verified through dashboard and MCP parse/create/persist: one delivery recipient and
  699 distinct saved rejected sources, with the preview reporting 199 truncated rows.
  Primary identity fields remain unchanged; bounded alternates cannot grow per person.
  Direct create/add preserves duplicate source rows too. Historical rows already lost
  by the former 500-row truncation require the original file to be reimported.
- Explicit staff resolution creates pending trip membership only. It rechecks the
  current source tenant/group, revision, content/name/phone fingerprint, key version,
  group/configuration revisions and identifier semantics. Changed sources require a
  new preview. Refreshing unresolved cases preserves human resolutions and authorized
  replacement candidates. Source-only locks avoid locking joined broadcast rows.
- Staff source listing uses selective cursor pages (default 25, max 50), name search
  with the existing trigram prefilter and a bounded candidate projection query.
- Explicit enrollment requires accepted source/current revisions, configured purpose
  and notice, permission evidence, plus a reviewed target for updates. Missing issuer
  and document type require explicit document-view attestation, not nationality or
  place-of-issue inference. Retry HMAC binds the complete enrollment payload.
- Lost/cancelled/compromised/disputed/rejected passport identities cannot be revived
  by enrolling a new scan. A reviewed renewal creates another identity for the same
  person. Later accepted issue dates can become future defaults; trip references freeze.
- Public replacement-candidate linkage requires a live grant/review version AND the
  fresh upload's own X-Upload-Session-ID capability. It binds one source to the selected
  person, preserves provisional status, and records a keyed digest of source fields
  and images. Staff must approve the source and acknowledge the selected-person
  association during enrollment. Changed content requires fresh association. Ordinary
  staff approval revision increments with unchanged content remain valid.
- Independent original copies are queued durably and performed server-side without
  loading document bodies into the worker. Global PostgreSQL copy admission <= 2,
  attempts <= 5, explicit provider timeout envelope, stable destinations, post-copy
  size/checksum checks and live authorization both before and after I/O.
  MIME-derived allowlisted extensions are durably bound before copying; copied MIME
  must match and cannot change between retries. Older extensionless exports use the
  existing validated archive handling rather than trusting a guessed filename.
- Shared private media policy permits JPEG/PNG/WebP/PDF <= 20 MiB. Pending, purged,
  unsupported, expired or unreadable assets cannot satisfy reuse requirements.
- Group/source deletion detaches operational FKs and preserves immutable provenance.
  Pending copies block unsafe source deletion. Cleanup consults retained ownership;
  copied originals cannot be deleted as incidental old-group assets.
- Future-reuse withdrawal immediately revokes historical access. Lawful current-trip
  snapshots retain their own referenced data until the operational source is removed.
  Asset purge/hard profile deletion immediately denies staff image/thumbnail access.
- Staff confirmation/single/bulk approval synchronizes the current participation once
  and records its accepted source extraction revision; it does not silently promote
  edited trip fields into retained identity evidence.
- ZIP preparation uses batched retained-asset authorization (<= 200 sources / 1,000 assets
  per query), rechecks immediately before and after rendering, and closes the spool if
  authority was removed during generation. MCP's existing re-preparation around upload
  also uses this guard. Previously published artifacts need their own download-time
  revocation checks; do not confuse generation guards with permanent artifact erasure.
