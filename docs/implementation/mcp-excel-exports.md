# MCP Excel export generation — local qualification

The implemented family is passport Excel: one group in all/incremental mode, selected groups in all mode, or an exact selected list of passports in all mode. The shared preparation functions now feed both the existing website routes and MCP. They preserve website fields, WhatsApp identity/agency matching, pending recipients, optional airport grouping, ECR labels and formula escaping. ECR reads persisted results; it does not invoke a provider.

## Tool contract

- `inspect_excel_export` takes an explicit agency, one to 100 exact group IDs and the requested selection/options. It returns the render-input revision, counts and available fields. It creates no workbook, history or storage client.
- `prepare_excel_export` takes those same arguments, the inspected revision and a stable 16–256-character idempotency key. It first commits a DB-only queued operation receipt. In a separate transaction it renders and stores the workbook and marks generation succeeded. The initial receipt remains immutable and queued; the current operation observation separately records `prepared_for_delivery`.
- `resume_excel_export` takes the saved operation UUID. A queued request revalidates the original revision. A succeeded request recovers the existing unexpired artifact after current authority/scope/checkpoint checks. It never regenerates an expired result. A different authorized connection for the same actor gets its own access locator to the same artifact/history.

Selected passport IDs must all be available within the explicitly supplied groups. Missing IDs never silently disappear. Incremental mode is allowed only for a single group and requires a completed compatible baseline. Selected exports deliberately have no incremental history checkpoint, matching the website contract.

## Persistence, locks and bounds

`MCPOperationService` persists only the validated request and expected revision inside the queued callback. The callback performs SQL preparation and validation only. Workbook rendering, temporary files and S3 writes occur later, outside that callback. The original operation UUID becomes the group history request UUID, and completion links one artifact UUID to the operation. DB rollback leaves the committed queued request available for an explicit retry; an orphan private object is subject to the transfer-prefix expiry policy.

Generation revalidates control, current grant/capability and identity before locking the operation. It locks groups in UUID order, then linked broadcasts, link/recipient rows and retained passport rows. Source locks use `NOWAIT`: a legacy writer can hold a passport before its roster-revision trigger updates the group. Waiting in the opposite order could deadlock, so a busy source aborts generation safely and the caller retries the same operation later. Current render inputs are hashed and compared before rendering, after rendering, and after private storage before the history/artifact/operation transaction commits.

All MCP export families share one nonwaiting kernel lease per backend container for inspection, preparation and generation; the existing per-process limit is a secondary guard. Workbook and storage worker threads are drained even after repeated cancellation before capacity is released. The selection is bounded to 100 groups, 1,500 exportable passports and 1,500 linked active recipient records; field selection is bounded to 256 keys. Existing combined-export rules also cap emitted rows including pending recipients. Passport Excel additionally caps canonical snapshots at 16 MiB, resolved catalog fields at 256, actual columns at 320, a conservative cell envelope at 250,000, and generated XLSX output at 32 MiB. Rendering has a 120-second deadline with native-worker drain. Transfer chunk/deadline rules remain those of the artifact service. The snapshot check follows ORM materialization, so these limits do not bound a single earlier load of unusually large retained JSON/text; full source-size preflight and mixed-load RSS qualification remain open. These bounds require measured production memory/load qualification; they are not a claim of constant-memory XLSX generation.

Delivery uses the authenticated artifact HTTP API. Generation does not mark a passport export completed. Only a complete checksum-valid server stream followed by the connector's verified local delivery acknowledgement invokes the shared website completion transition. Recovering or repeating delivery preserves one history completion.

## Evidence

- `backend/tests/integration/test_mcp_exports.py`: 10 tests, real XLSX row/cell parity against the website, incremental payload and cumulative baseline, acknowledgement-only completion, immutable receipt replay, one artifact/history across connection recovery, stale revision and storage rollback, exact selected groups/passports, missing secondary group, expiry and legacy version-0 link preservation, unsupported mode validation, and proof that the queued callback neither initializes storage nor renders a workbook.
- Focused artifact/export/website regressions: 49 tests passed. Shared exporter, ECR, phone, pending-row and route-decomposition regressions: another 148 tests passed.
- `backend/tests/service_integration/test_mcp_exports_postgresql.py`: 3 tests passed against the disposable loopback PostgreSQL database after migration 0115. Two connections generate/recover one workbook/history; a passport-first correction returns source-busy without deadlock and subsequently invalidates the revision; revocation wins before generation. The existing 2 artifact PostgreSQL race tests also passed.
- `mcp-connector/tests/test_exports_tcp.py`: the official MCP SDK client → local connector → real loopback TCP backend path passed inspection, generation, identical-key retry, atomic verified local save, workbook reopening, delayed acknowledgement and completed-result recovery. The backend uses an isolated synthetic SQLite fixture and a private-storage double.
- Scoped Ruff and mypy checks passed for the touched production files.

No production storage, external provider, real browser/MFA/vault session or real Codex attachment delivery participated. This does not qualify other export families, uploads/business ingestion, deployment expiry policies, production capacity, or the full Phase 4 release gate.
