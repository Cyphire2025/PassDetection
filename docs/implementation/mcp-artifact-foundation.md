# MCP artifact foundation — local qualification

This is the first Phase 4 transfer increment. It stages a PDF for an existing agency/group, protects generated temporary exports, and completes a prepared passport export checkpoint only after a complete server stream and the connector's verified local delivery acknowledgement. It does not constitute completion of Phase 4.

## HTTP and service contract

Every endpoint requires a dedicated MCP access bearer token, an active superadmin and connection, and the current connection **and deployment** capability. Dashboard JWTs are rejected. New handles are opaque HMAC-derived locators bound to a random artifact UUID, actor and grant, with only protected hashes stored. An access record authorizes each individual grant. Legacy random handles retain their original version-0 access record. Foreign connections receive not-found. No endpoint accepts a storage key, server path, arbitrary URL, or filesystem command.

| Endpoint | Contract |
|---|---|
| `POST /mcp/artifacts/uploads` | `application/pdf` stream; explicit agency/group/filename query; `X-Artifact-Size` and `X-Artifact-SHA256`; rejects mismatches, validates/scans through `UploadSecurityService`, stores a private transfer copy. Returns `business_ingestion: not_started`. |
| `GET /mcp/artifacts/{handle}` | Connection-bound size, SHA-256, expiry, purpose, group and protected content path. |
| `GET /mcp/artifacts/{handle}/content` | Authenticated exact stream with size/SHA-256 headers. Range requests are unsupported. A full, checksum-valid stream records `download_completed_at`; it does not complete export history. |
| `POST /mcp/artifacts/{handle}/delivery` | Bounded JSON exact size/SHA-256 acknowledgement. Requires a full-stream marker and current authority. Completes the associated prepared history using the same application service as the website. Repeated acknowledgements are idempotent. |

Only reviewed code can call `prepare_export` with generated bytes. Initial allowed purposes are `passport_excel` and `passport_images`; the HTTP API cannot register arbitrary generated content. Export associations require the exact history user, group, agency, kind and immutable checkpoint. The artifact captures a canonical checkpoint fingerprint and rejects a changed checkpoint at acknowledgement. The service leaves transaction commit to its caller.

Temporary artifact metadata cascades only when the existing manual agency/group/history removal flow removes its source association. It cannot initiate a business deletion. There is no deletion, archive, replacement or removal tool in this increment. User/grant association restrictions remain explicit.

Combined exports retain every exact agency/group pair (at most 100). Every metadata read, content request and acknowledgement revalidates every pair; a missing secondary group denies the entire artifact. Receipt recovery can grant a newly authorized connection its own locator to the same artifact and history, after checking actor, current authority, associations, expiry and checkpoint. It cannot reconstruct an original version-0 locator for the same grant, so that case explicitly reports unavailable while preserving the original link. Recovery never extends expiry or rebuilds an expired result.

## Bounds and recovery

- PDF ingress streams to a private temporary file. Its actual received length is bounded by the existing upload setting (default 10 MiB), even when the declared size is false. The existing PDF scanner/parser requires one bounded in-memory copy after ingress; this is not a constant-memory scan implementation.
- Exports spool at most 512 MiB and use 64 KiB storage transfer chunks. Two transfers can run concurrently per API process. Limits therefore multiply by the deployment's worker count and still require a measured production capacity gate.
- Transfers have a 120-second application deadline. Storage writes reuse the existing cancellation-draining helper, so a cancelled request does not close a source while the S3 worker is still reading it. Boto's configured network deadlines also apply.
- Private S3 keys are server-generated under `mcp-transfers/v1/`. Writes require `If-None-Match: *`; an unsupported conditional-write provider fails closed. Existing objects are never overwritten.
- Artifact access expires after one hour. Physical expiry of private copies, including an object written immediately before a database failure or process death, needs a deployment storage lifecycle policy restricted to that prefix. This policy is a remaining gate; the connector cannot remove source objects.
- The server can verify its stream and the acknowledged digest/size; it cannot independently prove a remote filesystem save. The connector creates that evidence by atomically publishing a verified local file before sending the acknowledgement. If acknowledgement fails, its result preserves the absolute file path and reports `server_delivery_acknowledged: false`. Explicit recovery rehashes the chosen file before another acknowledgement.
- Temporary local files are removed on handled failures/cancellation. A process kill may leave an uncommitted private `.gcmcp-*.part` file. It is never a successful delivery.

## Evidence and remaining gates

`backend/tests/integration/test_mcp_artifacts.py` exercises the real SQL model, HTTP routes, existing PDF parser/security service, authority changes, foreign grants, scoped association, ingress bounds/checksum, failed scans, interrupt/corruption handling, immutable checkpoints, capability rollout disable, conditional writes and cancellation drain. Storage and scanner outcomes are synthetic in these tests. Existing website history tests pass against the extracted shared completion service.

`backend/tests/service_integration/test_mcp_artifacts_postgresql.py` passed on the disposable loopback PostgreSQL database after the complete migration chain through 0115: six concurrent acknowledgements create one history completion/audit; a committed revocation wins before a blocked acknowledgement. The test fixture rejects non-local/non-test database targets.

`mcp-connector/tests/test_backend_tcp.py` starts the real OAuth, artifact and MCP HTTP adapters under uvicorn using an isolated SQLite file and synthetic identity. It verifies PDF upload through the typed client and existing security service with a persisted scan decision, then creates a synthetic valid XLSX, downloads it through real TCP, atomically verifies/publishes it, reopens it, and confirms delayed history completion. S3 storage is an in-memory test double and malware scanning uses the explicitly permitted development scanner. This is not production ClamAV/S3/Nginx qualification or a real Codex/browser/MFA/vault sign-in.

The group all/incremental, selected-group and selected-passport Excel adapters are now locally qualified; see [Excel export contract](mcp-excel-exports.md). Remaining Phase 4 work includes other export families, Excel/image upload lanes and business ingestion adapters, private-copy lifecycle configuration, interrupted production storage tests, real Codex file workflows and production capacity qualification. Connector CLI transfer commands and typed client were qualified at 0.2.0; connector local file-tool registration is a separately evolving increment. No Codex configuration or private credential storage was modified.
