# Additive group-to-broadcast association

This locally qualified slice exposes `inspect_group_broadcast_addition` and `add_group_broadcast_link`. It adds one exact agency/group/broadcast association per intended operation and retains every existing link. It does not complete the remaining-domain or production qualification gate.

Inspection returns a SHA-256 `source_revision`, separate source-row/contact/destination counts, retained shared-destination count, issue counts and the exact proposed matching fields. Names are untrusted business data. The revision binds the current group, every existing link, target broadcast configuration, target retained contacts/recipients, operational source projection, replacement exclusions and complete mobile identity proposal. New requests must use that unchanged revision. Durable operation keys recover the original immutable receipt across connections owned by the same current user.

Bounds are 100 retained group links, 5000 source submissions, 5000 retained/proposed target source contacts, 5000 retained/proposed recipient rows, 5000 retained/proposed mobile identities, and the shared 1500 active-recipient ceiling. Exceeding a bound rejects the complete operation. The exact source selection uses the same office-visible status and operational roster predicates as website source synchronization. Mobile provisioning separately uses all office-visible source submissions, matching the canonical mobile planner's collection-contact authority. Imported spreadsheet phones never become mobile login authority.

Ordinary groups add association metadata. Import-only groups may add missing source contacts and unique delivery destinations using the canonical `build_source_contacts` projection. Shared phones retain every source traveller, reuse an unchanged active destination and create at most one new destination. Missing/invalid phone and name diagnostics remain retained per source row. Existing recipient names, phones, ownership and imported fields are never overwritten. Removed, merged or suppressed destination collisions block rather than revive. Conflicting retained source associations and existing traveller overrides block rather than overwrite or discard. A link that would require suppressing an active recipient under retained replacement rules also blocks. An existing exact link returns unchanged; different matching configuration is rejected.

Before any link/contact/recipient persistence, the complete canonical mobile plan is compared with locked existing identities. Any existing binding change, reactivation or revocation blocks. Only new identities and their normal journal entries may be created by the shared applier after the pure preflight. Existing identity state and session revocation helpers remain untouched. The canonical private-delivery guard runs with `cancel_queued=False` for both the group and target broadcast, while group/broadcast/ledger locks remain held through outer commit. Queued, processing and unknown private delivery all block; no queue is cancelled and no messages are sent.

Receipt access checks current superadmin/tenant/group/broadcast policy, exact retained link/configuration, retained source association bindings and live recipients. Receipts/audits contain identifiers and counts rather than raw phone numbers, source documents or credentials. No schema migration is required.
